# U9 — unknown-product browser acceptance (Stas)

Dependencies: U5 #111 → U6 #109 → U7 #112 → U8 #113 → guided-entry fixes #114.
This PR contains the test harness and CI changes; dependency implementation stays in its own PRs.

Run with Node 22+ and the pinned pnpm:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium webkit
EXPO_PUBLIC_NUTRITION_ENRICHMENT=1 pnpm e2e:web:build
EXPO_PUBLIC_NUTRITION_ENRICHMENT=1 pnpm e2e:web
```

The enrichment flag enables the action only for this local stub build. Hosted previews retain U8's backend-readiness gate.
`unknown-stubs.mjs`, called by `server.mjs`, isolates sessions by device ID, records actual requests, and can hold/release reads or saves.
Images are transport-only copies of the existing icon; product, nutrition and category facts come from the existing demo fixture and category data.

Local macOS WebKit rejects a standalone IndexedDB Blob write with `UnknownError: Error preparing Blob/File data to be stored in object store`.
This prevents local Safari photo-flow acceptance; the Safari assertions remain enabled in Linux CI. Android/Chromium evidence does not establish physical-phone acceptance.
The CI JWT-secret alias supplies the existing expired-token fixture from the disposable stack's `JWT_SECRET`; no hosted secret or backend code is changed.
